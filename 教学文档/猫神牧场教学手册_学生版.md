# 猫神牧场教学项目学生手册

> 本手册面向第一次接触这个项目的同学。你不需要改动游戏核心逻辑，只需要学会配置场景、创建资源、编写能力脚本，并把资源和脚本正确接起来。

## 1. 项目里最重要的三条线

在这个教学项目里，先记住三句话：

- 场景对象负责“游戏怎么摆、怎么连”。
- Data 资源负责“动物、能力、道具、玩具是什么”。
- 脚本注册表负责“某个能力到底由哪段代码执行”。

也就是说，新增一个动物通常不是只建一个文件，而是要同时处理：

1. 动物资源 `AnimalData`
2. 能力资源 `AbilityData`
3. 能力脚本 `YourAbilityEffect.cs`
4. 注册表 `AbilityEffectRegistry`

如果能力不生效，优先检查资源和注册名是否一致，不要一上来就改核心逻辑。

## 2. 场景里要认识的对象

### 2.1 RanchManager

在 Unity 的 Hierarchy 里点击 `RanchManager` 对象，可以在 Inspector 里配置牧场的主要参数。

常用字段如下：

| 字段 | 作用 | 新手建议 |
|---|---|---|
| `mapWidth` | 地图宽度 | 教学中通常保持默认，例如 4 |
| `mapHeight` | 地图高度 | 教学中通常保持默认，例如 5 |
| `day` | 初始天数 | 一般从 1 开始 |
| `money` | 初始金币 | 按课堂测试需要设置 |
| `cans` | 初始罐头 | 用于移除动物等操作 |
| `removeAnimalCansCost` | 移除动物消耗的罐头数量 | 新手阶段保持默认 |
| `ranchMap` | 场景中的牧场地图对象 | 必须拖入正确对象 |
| `autoPopulateOfferPoolByFamily` | 是否按动物家族自动生成抽卡池 | 教学项目建议开启 |
| `offerPoolFamilies` | 参与抽卡的动物家族 | 例如 `Hoofed` |
| `offerRoller` | 抽卡规则组件 | 有就拖入，没有时会用备用逻辑 |
| `animalViewPrefab` | 动物显示用预制体 | 必须配置，否则动物可能不显示 |
| `fallbackAnimalSprite` | 动物兜底图片 | 动物没有图标时使用 |
| `randomStartingAnimalCount` | 开局随机生成的动物数量 | 课堂演示时可以调小 |
| `startingItems` | 开局拥有的道具 | 新手阶段可以为空 |
| `equippedToys` | 开局装备的玩具 | 新手阶段可以为空 |

操作步骤：

1. 在 Hierarchy 中选中 `RanchManager`。
2. 在 Inspector 中确认 `ranchMap` 已经指向场景中的地图对象。
3. 确认 `animalViewPrefab` 已配置。
4. 如果要控制抽卡内容，检查 `offerPoolFamilies`。
5. 点击 Play 后，观察是否能生成初始动物、点击地块、进入下一天。

### 2.2 地块合集与 RanchTileSystem

场景中的地块一般放在一个地块根对象下面。这个对象或其相关对象上可能有 `RanchTileSystem` 组件，用来配置地块类型。

常用字段如下：

| 字段 | 作用 | 新手建议 |
|---|---|---|
| `defaultTileType` | 默认地块类型 | 一般设为 `Normal` |
| `tileSprites` | 每种地块类型对应的图片 | 给不同地块类型绑定 Sprite |
| `cellOverrides` | 指定某个坐标是什么地块 | 用于设置特殊地块 |

`tileSprites` 中每一项通常包含：

- `tileType`：地块类型
- `sprite`：地块图片
- `sizeMultiplier`：显示缩放
- `updateColliderSize`：是否同步更新碰撞体大小

`cellOverrides` 中每一项通常包含：

- `coords`：地块坐标，例如 `(0, 0)`
- `tileType`：这个坐标使用的地块类型

### 2.3 SceneGridCellMarker

每个可点击地块上需要有 `SceneGridCellMarker`，它保存这个地块的网格坐标。

字段：

| 字段 | 作用 |
|---|---|
| `gridCoords` | 当前地块在地图中的坐标 |

如果地块很多，不建议手动一个个填。可以使用菜单：

```text
Tools/Game/Assign Scene Grid Coords From Position
```

使用方法：

1. 在 Hierarchy 中选中地块根对象。
2. 点击菜单 `Tools/Game/Assign Scene Grid Coords From Position`。
3. 工具会根据地块在场景中的位置自动写入坐标。

## 3. 创建动物资源

动物资源类型是 `AnimalData`。

建议放置位置：

```text
Assets/Game/Data/Animals/[Family]/
```

例如：

```text
Assets/Game/Data/Animals/Hoofed/pig.asset
Assets/Game/Data/Animals/Hoofed/boar.asset
Assets/Game/Data/Animals/Hoofed/horse.asset
```

创建方法：

1. 在 Project 窗口中打开对应文件夹。
2. 右键空白处。
3. 选择 `Create > Nekogami Ranch > Animal Data`。
4. 修改资源文件名。
5. 在 Inspector 中填写字段。

常用字段：

| 字段 | 作用 | 填写建议 |
|---|---|---|
| `id` | 动物 ID | 用英文或拼音，保持唯一 |
| `animalName` | 显示名称 | 玩家看到的名字 |
| `family` | 动物家族 | 例如 `Hoofed` |
| `rarity` | 稀有度 | 0 到 4 |
| `baseMoney` | 基础收益 | 每日结算时使用 |
| `evolutionThreshold` | 进化阈值 | 不做进化时可为 0 |
| `evolutionTarget` | 进化目标动物 | 不做进化时可为空 |
| `ability` | 绑定能力资源 | 拖入对应 `AbilityData` |
| `description` | 动物描述 | 简短说明 |
| `icon` | 动物图标 | 建议必须配置 |
| `familyIcon` | 家族图标 | 可选 |
| `iconScale` | 图标缩放 | 默认 1 即可 |

注意：

- `id` 不要重复。
- `ability` 如果为空，这个动物就没有能力。
- 如果动物进了抽卡池但不显示，优先检查 `icon` 和 `animalViewPrefab`。

## 4. 创建能力资源

能力资源类型是 `AbilityData`。

建议放置位置：

```text
Assets/Game/Data/Abilities/Animals/[Family]/
```

例如：

```text
Assets/Game/Data/Abilities/Animals/Hoofed/PigAbility.asset
Assets/Game/Data/Abilities/Animals/Hoofed/BoarAbility.asset
Assets/Game/Data/Abilities/Animals/Hoofed/HorseAbility.asset
```

创建方法：

1. 在 Project 窗口中打开能力资源文件夹。
2. 右键空白处。
3. 选择 `Create > Nekogami Ranch > Ability Data`。
4. 修改资源文件名。
5. 填写能力字段。
6. 回到动物资源，把这个能力拖到动物的 `ability` 字段上。

常用字段：

| 字段 | 作用 | 填写建议 |
|---|---|---|
| `id` | 能力 ID | 建议和能力资源名接近 |
| `abilityType` | 能力类型 | 新手阶段可保持默认 |
| `priority` | 优先级 | 数字越小越早执行，具体按项目规则 |
| `impactType` | 作用范围 | 例如 `Self`、`Adjacent`、`Row` |
| `stackable` | 是否可叠加 | 看能力是否允许叠加 |
| `desc` | 能力说明 | 会显示给玩家或用于说明 |
| `triggerType` | 触发时机 | 例如 `SettlementPrepare`、`DayStart`、`Moved` |
| `triggerChancePercent` | 触发概率 | 100 表示必定触发 |
| `triggerLimit` | 触发次数限制 | 0 通常表示不限制 |
| `effectType` | 效果类型 | 例如 `AddMoney`、`Breed`、`SellSelf` |
| `effectScriptId` | 具体执行脚本 ID | 必须和注册表 key 完全一致 |
| `effectParams` | 效果参数 | 例如钱数、延迟天数、目标家族 |
| `subAbilities` | 子能力列表 | 新手阶段一般不用 |

最关键的是：

```text
AbilityData.effectScriptId == AbilityEffectRegistry 里的注册 key
```

只要这个名字不一致，能力就不会执行。

## 5. 创建能力脚本

能力脚本负责真正执行效果。

建议放置位置：

```text
Assets/Game/Scripts/Abilities/[Family]/
```

例如有蹄类动物能力可以放在：

```text
Assets/Game/Scripts/Abilities/Hoofed/
```

通用能力可以放在：

```text
Assets/Game/Scripts/Abilities/General/
```

能力脚本通常需要：

1. 创建一个 C# 脚本。
2. 类名和文件名一致。
3. 实现 `IAbilityEffect`。
4. 在 `Execute` 方法里写能力逻辑。
5. 在 `AbilityEffectRegistry` 中注册。

一个能力脚本的大致结构如下：

```csharp
using System.Collections.Generic;
using NekogamiRanch.Animals;

namespace NekogamiRanch.Abilities
{
    public class YourAbilityEffect : IAbilityEffect
    {
        public bool Execute(
            AnimalAbilityContext context,
            AbilityData abilityData,
            IReadOnlyList<Animal> targets)
        {
            if (context == null || context.Owner == null || context.RanchManager == null)
            {
                return false;
            }

            // 在这里写你的能力效果
            return true;
        }
    }
}
```

新手阶段建议先模仿：

```text
Assets/Game/Scripts/Abilities/Hoofed/PigAbilityEffect.cs
Assets/Game/Scripts/Abilities/Hoofed/BoarAbilityEffect.cs
Assets/Game/Scripts/Abilities/Hoofed/HorseAbilityEffect.cs
```

## 6. 注册能力脚本

能力脚本写好以后，还不能自动生效。你需要把它注册到：

```text
Assets/Game/Scripts/Abilities/AbilityEffectRegistry.cs
```

在字典里追加一行：

```csharp
{ "YourAbilityEffect", new YourAbilityEffect() },
```

然后在对应 `AbilityData` 里填写：

```text
effectScriptId: YourAbilityEffect
```

检查顺序：

1. 脚本文件名是不是 `YourAbilityEffect.cs`
2. 类名是不是 `YourAbilityEffect`
3. 注册表 key 是不是 `"YourAbilityEffect"`
4. 能力资源 `effectScriptId` 是不是 `YourAbilityEffect`
5. 动物资源 `ability` 有没有拖入这个能力资源

这五个地方只要有一个没对上，能力就可能不生效。

## 7. 道具和玩具怎么接

本阶段重点是动物和能力。道具、玩具可以后续课程再做，但它们的接入方式很相似。

### 7.1 道具

资源位置：

```text
Assets/Game/Data/Items/
```

脚本位置：

```text
Assets/Game/Scripts/Items/
```

注册表：

```text
Assets/Game/Scripts/Items/ItemEffectRegistry.cs
```

规则：

```text
ItemData.effectScriptId == ItemEffectRegistry 里的 key
```

### 7.2 玩具

资源位置：

```text
Assets/Game/Data/Toys/
```

脚本位置：

```text
Assets/Game/Scripts/Toys/
```

注册表：

```text
Assets/Game/Scripts/Toys/ToyEffectRegistry.cs
```

规则：

```text
ToyData.effectScriptId == ToyEffectRegistry 里的 key
```

## 8. 基础测试流程

每次新增动物或能力后，按这个顺序测试：

1. 回到 Unity，等待脚本编译完成。
2. 检查 Console 有没有红色报错。
3. 打开动物资源，确认 `ability` 已绑定。
4. 打开能力资源，确认 `effectScriptId` 已填写。
5. 打开注册表，确认有对应 key。
6. 点击 Play。
7. 观察动物是否出现。
8. 点击结算或下一天，观察能力是否触发。

## 9. 常见问题

| 现象 | 常见原因 | 检查位置 |
|---|---|---|
| 动物不显示 | `animalViewPrefab` 没配，或动物 `icon` 为空 | `RanchManager`、`AnimalData` |
| 地块点不了 | 地块没有碰撞体，或坐标标记不完整 | 地块对象、`SceneGridCellMarker` |
| 能力不触发 | `effectScriptId` 和注册表 key 不一致 | `AbilityData`、`AbilityEffectRegistry` |
| 抽卡没有新动物 | 动物 family 不在 `offerPoolFamilies` 中 | `RanchManager` |
| 能力脚本报错 | 类名、命名空间、接口实现不正确 | 新增的能力脚本 |
| 修改后没变化 | Unity 没编译完成或资源没保存 | Console、Project 资源 |

## 10. 给新手的工作顺序

推荐你每次新增内容都按这个顺序：

1. 想清楚动物设定。
2. 创建动物资源。
3. 创建能力资源。
4. 编写能力脚本。
5. 注册能力脚本。
6. 把能力资源拖到动物资源上。
7. 检查 `RanchManager` 是否能把这个动物加入候选池。
8. 运行测试。

不要同时做很多动物。一次只做一个，跑通以后再做下一个。

## 11. 使用 vibecoding 工具时的提示词模板

如果使用 vibecoding 工具生成内容，建议使用下面这种提示词：

```text
请只为猫神牧场教学项目新增一个动物内容包，不要修改核心游戏逻辑。

允许新增或修改：
- AnimalData
- AbilityData
- 一个新的 IAbilityEffect 能力脚本
- AbilityEffectRegistry 中的一条注册项

禁止修改：
- RanchManager
- RanchMap
- MapCell
- RanchTurnService
- RanchSettlementService
- RanchOfferService
- UI 脚本
- 抽卡逻辑
- 结算逻辑

请参考家猪、野猪、马的资源和脚本写法。
请先列出准备新增的文件，再生成内容。
```

如果工具想改核心逻辑，请停止并重新约束它。

## 12. 最后检查清单

提交前确认：

- 动物资源已创建。
- 能力资源已创建。
- 能力脚本已创建。
- `AbilityEffectRegistry` 已注册。
- `AnimalData.ability` 已绑定。
- `AbilityData.effectScriptId` 和注册表 key 完全一致。
- Unity Console 没有红色报错。
- Play 模式下可以看到动物。
- 点击结算后能力能按预期触发。

记住：这个项目的学习重点不是乱改系统，而是学会在已有框架中扩展内容。
