# 动物家族与动物池更新目录

## 更新目的

本目录记录两部分更新：

1. 动物配置支持“第二家族”。
2. 游戏开始界面的家族选择会联动本局游戏动物池。

## 一、双家族动物支持

本次更新为动物配置表增加“第二家族”字段。动物可以同时属于主家族和第二家族，并且会被对应的图鉴分类、家族筛选、随机生成、能力目标判断、捕食/保护规则识别到。

示例：

- 主家族 `Bird`
- 第二家族 `Carnivora`

该动物会同时被鸟类筛选和食肉类筛选检测到。

## 二、开始界面家族选择与动物池联动

游戏开始界面的家族 Toggle 会保存当前玩家选择的家族。进入游戏场景后，`RanchManager` 会读取该选择，并在刷新动物候选池前覆盖本局的 `offerPoolFamilies`。

保存示例：

```text
SelectedAnimalFamilies = Hoofed,Bird,Carnivora
```

这样开局随机动物和每日抽卡候选动物都会来自玩家选择的家族。

## 文件改动说明

`AnimalData.cs`

- 新增 `secondaryFamily` 字段，Unity 检查器中显示为“第二家族”。
- 新增 `SecondaryFamily` 只读属性。
- 新增 `HasFamily(string familyId)` 方法。
- 主家族或第二家族任意一个匹配时，`HasFamily` 都会返回 `true`。

`RanchContentCatalog.cs`

- 自动按家族生成动物候选池时，改为使用 `HasFamily`。
- 双家族动物会进入两个家族对应的候选池。

`RanchAnimalSpawnService.cs`

- `TrySpawnRandomFromFamily` 支持从主家族或第二家族中筛选。
- `TrySpawnRandomOutsideFamilyAt` 会排除主家族或第二家族命中的动物。

`RanchContentPoolService.cs`

- Editor 下仍然使用 `RanchContentCatalog.LoadOfferAnimals(...)` 自动加载动物池。
- 非 Editor 运行环境下，增加按家族过滤 `abilitySpawnPool` 的兜底逻辑。
- 过滤时使用 `AnimalData.HasFamily(...)`，所以第二家族也会被识别。

`RanchManager.cs`

- 新增读取 `PlayerPrefs` 中 `SelectedAnimalFamilies` 的逻辑。
- `InitializeFromScene()` 和外部 `Initialize(...)` 刷新内容池前，都会先应用玩家选择的家族。
- 如果没有保存过家族选择，继续使用场景中 Inspector 配置的默认 `offerPoolFamilies`。

`HangingSignToggleVisual.cs`

- 新增 `family` 字段，用于记录当前 Toggle 对应的动物家族 ID。
- 新增 `Family` 只读属性，供选择器读取。
- 支持根据 Toggle 下的中文名称自动推导家族 ID：

```text
有蹄 -> Hoofed
鸟 / 飞禽 -> Bird
食肉 / 肉食 -> Carnivora
鼠兔 / 啮齿 -> Mouse-Rabbit
爬行 -> Crawling
水生 / 海洋 / 水族 -> Aquatic
昆虫 / 虫 -> Insect
```

- 如果在 Inspector 中手动填写了 `family`，会优先使用手动值。

`NChooseKToggleSelector.cs`

- 保留原来的 `SelectedOptionIndices` 下标保存逻辑。
- 新增 `SelectedAnimalFamilies` 保存逻辑。
- 玩家确认选择后，会把当前选中的家族保存为逗号分隔字符串。

`AnimalBookIconListController.cs`

- 图鉴分类筛选改为使用 `HasFamily`。
- 双家族动物会出现在两个对应家族的图鉴分类中。

`AbilityTargetResolver.cs`

- 能力通用目标筛选中的 `targetFamily` 改为识别第二家族。

`PreyTargetRule.cs`

- 捕食目标规则的目标家族和排除家族都会识别第二家族。

`ProtectionRule.cs`

- 保护者家族、被保护对象家族、捕食者家族判断都会识别第二家族。

具体能力脚本：

- `CoyoteAbilityEffect.cs`
- `HyenaAbilityEffect.cs`
- `OstrichAbilityEffect.cs`
- `PeacockAbilityEffect.cs`
- `MuskOxAbilityEffect.cs`
- `HippoAbilityEffect.cs`

这些脚本中原本直接比较 `animal.Data.Family` 的地方，已改为 `animal.Data.HasFamily(...)`。

## 学生手动替换步骤

1. 关闭 Unity，避免脚本正在被编辑器占用。
2. 按上方“需要替换的文件”列表，将文件复制到项目相同路径。
3. 如果系统提示是否覆盖，选择覆盖。
4. 重新打开 Unity，等待脚本重新编译。
5. 打开任意动物配置表，在检查器中找到“第二家族”字段。
6. 给需要双家族的动物填写第二家族，例如 `Carnivora`、`Bird`、`Hoofed`。
7. 打开游戏开始界面的家族选择 Toggle，确认每个 `HangingSignToggleVisual` 的 `family` 字段正确。
8. 如果自动识别不符合预期，可以手动填写家族 ID。

## 配置规则

- `family` 仍然作为主家族使用。
- `secondaryFamily` 是第二家族，可以留空。
- 资源文件不需要复制两份。
- 动物资源仍然建议放在主家族文件夹下。
- 开始界面家族 Toggle 的 `family` 必须和 `AnimalData.family` / `AnimalData.secondaryFamily` 使用同一套 ID。
- `NChooseKToggleSelector` 会把选中的家族写入 `PlayerPrefs` 的 `SelectedAnimalFamilies`。
- `RanchManager` 开局刷新动物池前会读取 `SelectedAnimalFamilies`。

例如：

```text
Assets/Game/Data/Animals/Bird/owl.asset
```

如果猫头鹰同时属于 `Bird` 和 `Carnivora`：

```text
family = Bird
secondaryFamily = Carnivora
```

## 验证方式

替换后可以用以下方式检查：

1. 找一个动物配置，填写第二家族。
2. 打开图鉴，切换到主家族分类，应能看到该动物。
3. 切换到第二家族分类，也应能看到该动物。
4. 如果有按家族触发的能力或捕食规则，该动物应能被对应家族规则检测到。
5. 在游戏开始界面只选择某几个家族并确认。
6. 进入游戏场景后，开局随机动物应只来自选中的家族。
7. 每日抽卡刷新出的动物也应只来自选中的家族。
8. 如果某动物的第二家族命中选中家族，也允许进入候选池。

## 注意事项

- 第二家族字段为空时，动物行为与旧版本一致。
- 不要为了双家族复制两份动物配置表，否则数值和能力容易不同步。
- 本次只支持一个第二家族。如果以后需要三个以上家族，建议再把字段升级为家族列表。
- `SelectedAnimalFamilies` 只影响本局候选动物池，不会修改动物配置资产。
- 如果没有确认过家族选择，游戏仍会使用 `RanchManager.offerPoolFamilies` 的默认配置。
- 打包运行时无法使用 Editor 专用的 `AssetDatabase`，所以需要确保 `abilitySpawnPool` 中已有可被运行时过滤的动物数据。
